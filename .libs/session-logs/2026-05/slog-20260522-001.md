## SLOG-20260522-001.概要 — 概要

yokemo プロジェクトから届いていた 6 件のエラーレポートを実害ベースで分類し、3 種のバグを本元 OS 側で修正、パッチ版 v1.5.2 として配信した。最大の実害だったのは `record.py:update_status()` の substring match バグで、TP テーブルの依存セルに書かれた他タスクの識別子まで誤って「完了」化される問題。yokemo SLOG-20260521-002 で詳細レポート + 修正案が提示されていたためその案を最小修正で取り込んだ。副次の BrokenPipeError ノイズと handler.py のシェルエスケープ問題もまとめて修正。

## SLOG-20260522-001.作業内容 — 作業内容

### 1. フィードバック確認

- 本元 `.claude/state/feedback/` 内の 2 件 (v1.0.0 / v1.3.0 由来) は対象コードが既に削除/修正済みで実害なしと確認
- yokemo の `.claude/state/feedback/` を確認 → 6 件のエラーレポートを発見
  - BrokenPipeError × 5 件 (load.py:314、実害小)
  - record.py の substring match バグ詳細レポート (yokemo SLOG-20260521-002 ベース、修正案つき)
  - 副次観測: handler.py が detail に `|` を含むと CMD で誤解釈される件

### 2. record.py:update_status() の修正

- バグ箇所: `task_id in line and "|" in line` の substring match
- 発火条件: 完了化対象 X の識別子が同一 TP テーブル内の別タスク Y の依存列に書かれていて、Y のステータスが置換対象 (未着手/進行中) のとき Y まで誤完了化される
- 修正: `line.split("|")` で cells に分割し `cells[TP_TABLE_TASK_ID_COL] == task_id` の完全一致に変更
- ローカル定数 `TP_TABLE_TASK_ID_COL = 2` を record.py 冒頭に追加 (L1 §1.2 モジュール固有内部定数として配置)

### 3. load.py:main() の BrokenPipeError 対策

- 単純な `try/except BrokenPipeError` では Windows で動かないことを実測で確認 (Windows ではパイプ閉鎖が `OSError [Errno 22] Invalid argument` で来る)
- Python 公式の SIGPIPE パターンに準拠: `try` の中で `print` + `flush` → 失敗時に `os.dup2(NUL, stdout.fileno())` で終了処理の自動 flush も静音化
- `except (BrokenPipeError, OSError)` で errno 22 / 32 のみ握り潰し (他の OSError はそのまま raise)

### 4. handler.py の argparse 化 + --detail-file 追加

- 既存の `sys.argv[3]` 直読みを `argparse` に置き換え
- `--detail-file PATH` オプションで UTF-8 ファイルから detail を読み込む経路を追加
- positional の `detail` も `nargs="?"` で残し、既存呼び出しを後方互換維持
- このセッション中の検証で `python -c "..."` 内の `|` が CMD に化ける現象を実際に再現できた (yokemo の副次レポートと一致)

### 5. 動作確認

- 一時テストスクリプト `.test_record_fix.py` / `.test_fixes.py` で yokemo SLOG-20260521-002 と同じ TP 構造を再現し、旧ロジックでバグ再現 (2 件誤ヒット) → 修正後 1 件のみヒットを確認
- load.py は subprocess で stdout を即閉じる相手にパイプして検証 → exit 0、stderr 0 行、feedback JSON 非生成
- handler.py は `|` を含む detail のファイル経由送信 + 旧 positional 形式の両方が成功

## SLOG-20260522-001.決定事項 — 決定事項

- **record.py の修正は yokemo SLOG-20260521-002 の提案案をそのまま採用** — TP テーブルの列構成は固定 (`| # | 識別コード | タスク | 依存 | ステータス |`)、`cells[2]` の index は機械的に決まる。ヘッダ位置の動的解析は過剰修正と判断
- **TP_TABLE_TASK_ID_COL は record.py のローカル定数として配置** — 他モジュールから参照されない値なので constants.py には移さない (L1 §1.2「モジュール固有の内部定数は該当モジュール冒頭」)
- **load.py の OSError catch 範囲は errno 22/32 に限定** — 全 OSError を握り潰すと load_task() 内の他の I/O エラーまで隠してしまう
- **handler.py は positional detail も残す** — 既存の呼び出し (`/fb` スキル等) を破壊しないため。新規シェルエスケープ問題は `--detail-file` で回避する設計
- **リリース戦略は v1.5.1 と同じ 2 コミット方式** — `fix:` 通常コミット + `release:` VERSION bump コミットを分けることで release.sh の commit が VERSION 1 行だけになり clean
